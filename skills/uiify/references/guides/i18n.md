# Localization

Use this guide when the project has an i18n setup (`next-intl`, `i18next`, `react-intl`, `@lingui/*`, `@inlang/paraglide-*`, or `locales/`, `messages/`, or `i18n/` folders), the request mentions languages, translation, RTL, Arabic, Hebrew or CJK, or the page declares `<html dir="rtl">`.

## Copy

Put every user-visible string in the project's message catalog. Pass translated UIify strings through `labels`, using `{name}` templates instead of concatenation, and pass the page language through `locale`. Do not leave UIify's English defaults on a non-English page.

## Direction and formatting

Set `lang` and `dir` on `<html>` on the server. UIify reads direction from the DOM; use `dir` props only for an island that differs. Use logical CSS such as `margin-inline-start`, `inset-inline-end` and `text-align: start` in custom styles. Mirror directional icons with `:dir(rtl)`.

Format numbers and dates with `Intl.*` and the page locale; do not hand-format them. Custom key handlers on text inputs should start with `isComposingKeyEvent(event)`.

## Typography and language picker

Avoid `letter-spacing` and uppercase styling on Arabic or CJK text. Let `:lang()` choose fonts. Use plain links and endonyms in a language picker, no flags, and mark the current language with `aria-current`.

## Verify

Render once with `dir="rtl"` and once with a long-text locale such as German or a pseudo-locale. Check overflow, popup anchoring and arrow keys.
